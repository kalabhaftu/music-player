Music Player Documentation

Local audio & video library manager built on Windows with a headless Rust core (music-player-core), native Slint UI (music-player-app), SQLite WAL persistence, and bundled LibVLC playback.

Overview

Music Player keeps your entire media library on your device with fast incremental scanning, gap-free / crossfaded audio playback, a 10-band equalizer with custom presets, synchronized lyrics, duplicate detection, and a dedicated native video window.

Headless Core Crate

All SQLite storage, metadata extraction (lofty), scanner pipelines, LRCLIB client, queue logic, and LibVLC FFI live in music-player-core.

Native Slint + Win32 UI

music-player-app drives responsive views, dynamic artwork palettes, SMTC media controls, tray integration, and child HWND video hosting.

Shared Database Schema

Uses SQLite in WAL mode (LibraryStore), reading the same library tables, playlists, settings, and scan state seamlessly.

Cold Start & Splash Screen Lifecycle

On launch, Splash::try_show() displays a lightweight Win32 splash card while the app initializes. The splash screen has no fixed sleep duration — it closes immediately once ui.show() paints the main window.

  1. Parallel LibVLC Pre-Warm: Before constructing AppWindow, a background thread (AudioEngine::prepare_vlc) loads libvlc.dll and LibVLC plugins concurrently while Slint initializes the window and theme.
  2. Instant First Frame: App::startup() populates settings, navigation, folder roots, the current view, and restored queue metadata from SQLite without blocking on LibVLC or Windows COM endpoint enumeration.
  3. Immediate Post-Paint Hydration: Right after ui.show() and dismissing the splash, complete_deferred_startup() attaches the pre-warmed LibVLC handle, enumerates MMDevice outputs, pre-stages the paused session track position, refreshes smart playlist counts, repairs missing artwork cache files, and triggers the background library scan.

Library Scanner & Incremental Updates

On startup, Music Player runs an incremental background scan (force_refresh = false) alongside a live LibraryFileWatcher for filesystem edits.

  • Artwork Cache Snapshot: LibraryScanSession snapshots cached artwork filenames once in memory rather than calling stat() per track during incremental checks.
  • Mtime + Size Fast Path: Unchanged files (same byte length, UTC timestamp, valid lyrics flag, and present artwork) are marked seen in batched 1,024-row cached SQLite statements without invoking metadata workers.
  • Bounded Parallel Pipeline: Changed or newly added files stream into a 2–4 worker HybridMetadataEngine pool and a dedicated single SQLite batch writer transaction.
  • Safe Pruning & Exclusions: Unseen tracks are pruned only inside completed, reachable roots while protecting offline drives, reparse points, and user-ignored folders.

Audio Engine, Equalizer & Crossfade

  • Perceived Volume Curve: Volume steps map cleanly with a quadratic perceptual loudness helper while preserving exact slider sync across the bottom bar, Audio pane, and Video window.
  • 10-Band Equalizer: ISO bands at 32, 64, 125, 250, 500, 1k, 2k, 4k, 8k, 16k Hz plus preamp. Moving any slider automatically switches Off to Custom and updates LibVLC live.
  • Dual-Player Non-Blocking Crossfade: When 2–10s crossfade is enabled (audio-only), a non-blocking state machine (Opening → Holding → Ramping) pre-buffers the incoming player and ramps equal-power gains cube-law compensated for VLC's Windows mixer.
  • Output Routing: Music routes via DirectSound (directx endpoint GUID selection), while video playback uses Windows mmdevice.

Video Playback Window & Format Defaults

Video extensions (.mp4, .m4v, .mkv, .avi, .mov, .wmv, .webm, etc.) default to Off during library scans until enabled in Settings → Library → Scan exclusions. You can also open video files directly from File Explorer at any time.

  • Dedicated Video Window: Playing a video opens VideoWindow hosting a native Win32 child surface HWND attached via libvlc_media_player_set_hwnd. Switching back to an audio track automatically detaches and closes the video window; closing the video window manually pauses video playback.
  • Sidecar & Embedded Subtitles: Automatically discovers up to 8 nearby .srt, .ass, .ssa, or .vtt files matching the video stem (exact match first, then stem.*) and lets you switch SPU tracks live.
  • Speed, Repeat, Snapshot & Fullscreen: Dedicated speed selector (0.5x–2x), single-video repeat toggle, PNG frame snapshots saved to Pictures\Music Player\Screenshots, and F11/Esc fullscreen.
  • Crossfade & Lyrics Excluded: Crossfading and automatic/online lyrics lookups are skipped for video files.

Lyrics & LRCLIB Pipeline

  1. Sidecar .lrc file next to the audio file is checked first; timed LRC lines always outrank untimed plain text.
  2. Embedded tag lyrics follow if no timed sidecar exists.
  3. When enabled in Settings, LRCLIB online matching normalizes featured artists/editions, checks duration proximity, filters censored matches, and saves matched timed lyrics when appropriate.

Build & Development Commands

# Run full Rust test suite (core unit/integration tests + app tests)
cargo test --manifest-path music-player-rust/Cargo.toml --workspace

# Check compilation without producing binaries
cargo check --manifest-path music-player-rust/Cargo.toml --workspace

# Build optimized local release executable
cargo build --release --manifest-path music-player-rust/Cargo.toml --bin music-player-app
